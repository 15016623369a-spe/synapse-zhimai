## 1. 两套评测

### A. MultiHop-RAG（主评测，公开基准）

```bash
backend/.venv/bin/python eval/prepare.py      # 下载 609 篇 + 导入隔离库
backend/.venv/bin/python eval/evaluate.py --all
```

- 数据：[MultiHop-RAG](https://huggingface.co/datasets/yixuantt/MultiHopRAG)（ODC-BY），609 篇英文新闻、2556 题；
- 题型：comparison 856 / inference 816 / temporal 583 / null 301；
- 每题有 gold 文章标题与证据句，标题与语料 100% 对齐；
- 全程离线、确定性；不调用 LLM。

### B. 10 题 demo 集（中文冒烟）

```bash
backend/.venv/bin/python scripts/eval_retrieval.py http://127.0.0.1:7800
```

只用于中文小语料回归，**不要对外引用为准确率**：16 篇文档取 top-8，随机命中率约 70%。

## 2. 结果（v2.6，全量 2556 题）

hash 向量 + BM25 + 文档级两阶段 + 英文子问题拆检索，top_k=10：

| 指标 | 全部（可答题） | comparison | inference | temporal |
|---|---:|---:|---:|---:|
| 题数 | 2254 | 856 | 815 | 583 |
| `doc_recall@10` | **0.544** | 0.645 | 0.378 | 0.628 |
| `hit@10` | **0.827** | 0.877 | 0.745 | 0.868 |
| `MRR@10` | **0.584** | 0.634 | 0.483 | 0.652 |
| `complete@5` | 0.176 | 0.285 | 0.029 | 0.221 |
| `complete@10` | 0.275 | 0.415 | 0.071 | 0.353 |
| `fact_recall@10` | 0.210 | 0.278 | 0.178 | 0.156 |
| `gap_false_positive` | **0.097** | 0.041 | 0.173 | 0.074 |
| `weak_false_positive` | 0.227 | 0.207 | 0.281 | 0.180 |
| `null_abstain`（强缺口） | 0.315 | – | – | – |
| `null_flagged`（含弱提示） | **0.861** | – | – | – |

怎么读：

- **随机基线**：609 篇取 10 篇，doc recall 约 `10/609 ≈ 1.6%`；0.544 约为随机的 34 倍。
- **comparison / temporal 明显好于 inference**：2 篇证据的题 hit@10 88%/87%，4 篇证据的推断题 75%；`complete@10` inference 只有 7.1%，说明「把四篇证据一次凑齐」仍是短板。
- **fact_recall@10 0.210**：命中文档不等于命中证据句，chunk 级精度仍是下一步重点。
- **严格缺口误报 9.7%**：可答题里只有不到 1/10 会弹「资料有限」卡片；另有 22.7% 会得到不打断的弱提示。
- **null 标记率 86.1%**：301 道无答案题里 86% 被强缺口或弱提示标记；其中强缺口 31.5%。

原始报告：[`eval/reports/multihop_rag_v1.json`](../eval/reports/multihop_rag_v1.json)。
复现耗时：1060s（单进程、无 GPU）。

### 与 v2.5 的对比

| 指标 | v2.5 | v2.6 |
|---|---:|---:|
| doc hit@10 | 0.778 | **0.827** |
| doc recall@10 | 0.472 | **0.544** |
| MRR@10 | 0.549 | **0.584** |
| complete@10 | – | **0.275** |
| fact recall@10 | 0.162 | **0.210** |
| gap 误报 | 0.365 | **0.097** |
| null 标记（含弱） | 0.705（仅强） | **0.861** |
| LCR | 0.75 | **0.85** |

提升来自三处：

1. **英文子问题拆检索**：长英文题按分号 / `, and` / `while` 切子问题（最多 3 条），而不是整句一个大 query；
2. **多查询文档轮转**：multi/compare 的候选文档按子查询轮流选，保证前排覆盖每个子问题；
3. **缺口两级化 + 单句证据信号**：强缺口（弹卡 + 联网）与弱提示（只提醒核对）分开，误报降了 26 个百分点。

## 3. 闭环收敛率（LCR）

```bash
backend/.venv/bin/python eval/loop_closure.py --questions 20
```

定义：

```
LCR = 采纳外部知识后由「答不上」变为「答得上」的题数
      ────────────────────────────────────────
      触发 gap 且完成采纳的题数
```

流程：16 篇中文 demo 语料 → 20 道 MultiHop-RAG 题（证据互不重叠）→ 先问确认 gap →
通过真实 `POST /api/extend/commit` 把证据文章入库（抓取用 MockTransport 模拟）→ 再问。

结果：**17/20 = 85%**；复问时引用到新文档 **18/20 = 90%**。

3 道失败题：2 道复问仍 gap 且没引用新文档；1 道引用了新文档但 gap 未消失。
失败样本与逐题记录见 [`eval/reports/loop_closure.json`](../eval/reports/loop_closure.json)。

## 4. 缺口判据（v2.6）

两级判定，避免「有引用的正确答案下面挂资料有限」：

| 级别 | 条件（英文/中文） | UI 行为 |
|---|---|---|
| 强缺口 `gap` | 无召回 / 硬实体未登录 / chunk 覆盖 < 0.20(英)·0.25(中) 且单句覆盖 < 0.10·0.15 且稀有词 ≤2 | 弹「知识库资料有限」卡片，可联网补充 |
| 弱提示 `weak` | chunk 覆盖 < 0.38·0.40 且单句覆盖 < 0.18·0.22 且稀有词 ≤3 | 一行灰色提示「匹配证据较少，建议核对引用」，不打断、不联网 |
| 无 | 其余 | 正常回答 |

单句证据信号的作用：长 chunk 里零散出现几个词也能把 chunk 覆盖率抬高；
但真正能支撑回答的往往是其中一句话。加单句覆盖后，可答题误报从 36.5% 降到 9.7%。

## 5. 已知限制

- **语言错配**：语料是英文新闻，产品主打中文笔记；tokenizer / 分块 / 阈值都按中文调过，英文数字是压力测试。
- **只测检索与拒答**：不测答案忠实度、引用精确率（后者由 `check_api.py` 与单测覆盖）。
- **hash 向量不是语义向量**：默认模式是词法哈希；`fastembed` 全量重建约 4–5 分钟，未作为评测默认。
- **null 题是构造出来的**：它们引用真实文章但问不存在的关联；现实中的「资料不足」更容易识别。
- **inference 的 complete@10 只有 7.1%**：4 篇证据的结构对 top-10 文档覆盖仍然苛刻，是下一阶段重点。
- **弱提示不计入强拒答**：`null_abstain` 只统计强缺口；对外引用时请同时给出 `null_flagged`。

## 6. 下一步

1. inference 的 4 文档覆盖：按子问题分别返回「一篇文档一个片段」，而不是共用 top-10；
2. fact-level CI 门禁：`fact_recall@10` 低于阈值直接失败；
3. 引用精确率评测：生成模式下对 `[n]` 与证据句做 NLI/蕴含校验；
4. 中文场景对照集：从个人笔记里抽 60 题，单独报告中文数字。
